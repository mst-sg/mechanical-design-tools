# Growth task and acceptance contract — 2026-09-27

## Purpose
Help engineers finish a small, verifiable task from a community-backed problem, through a tutorial and local tool, to a reviewed output. No customer files, credentials, arbitrary CAD automation claims or signoff guarantees.

## Project context
GitHub `mst-sg/mechanical-design-tools`, issue #16, branch `feat/16-engineering-labs`. Static public tools for mst-us.ai/tools; no database or customer CAD. Website publishing and other products have separate release procedures. Use synthetic, source-owned teaching assets only.

## UI plan
Existing React/TypeScript/CSS and static SG tool shell remain authoritative. Information order: task and limits, sample/download, input, explicit run, result with exact comparison basis, export, worked steps, related tutorial/product. No new UI library is needed.

Component trees:
- App > existing tool shell > RegisterCompare > before/after CSV fields > validation > comparison table > export > worked example.
- App > existing tool shell > DrawingToBom > existing OCR controls > BomLabGuide > downloads > correction exercise > expected comparison > manual.
- SG static shell > report-revision checker > local GDS selection + report manifest > explicit check > mismatch list > report download > tutorial.

States: empty inputs; reading/loading disables conflicting edits; malformed/duplicate data clears stale results; result export only after a successful run; changing any input invalidates results. Text labels and focus styles; table scroll on narrow screens, stacked input panels on mobile.

Self-review risks and corrections: too many cards (reuse existing sections); unreadable wide tables (scroll region); fake screenshots (capture actual local runs); hidden errors (role=alert, actionable text); oversized tutorials (jump links, steps, downloadable handbook).

## Verification oracle
Anonymous engineering reader, desktop Chrome and mobile Chromium/WebKit viewport. Synthetic fixtures only. Critical paths: sample -> run -> correct -> export -> compare with expected; corrupt/duplicate/missing inputs fail closed; download, canonical, sitemap, discoverable links and visible text. Collector: github referrer/UTM/localization, forged hostname rejection, QA separation, privacy opt-out. No raw filenames, input text or contents in telemetry. Capture screenshots and CSV/JSON outputs. Site HTML target <=5 seconds in the controlled test; OCR target <=120 seconds; distinguish client observations from field performance. No claims of real SolidWorks execution without a real CAD run.

Source classification does not backfill history. Repository views/clones, page views and completion/export metrics stay separate. D0 begins only at verified publication. Weekly review uses complete dated windows; D28 evaluates content directions, with no new automatic schedule created.
